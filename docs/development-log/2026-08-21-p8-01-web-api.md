## 2. 為什麼需要這項變更 (Why)
在 Phase 7 中，M.Ber 已經建立了由 `Planner` ➔ `Orchestrator` ➔ `Router` (LOCAL / MCP / A2A) ➔ `ResultAggregator` 構成的單一調度權威（Single Routing Authority）。

然而，先前的互動介面僅包含：
1. `app/cli.py`：命令列終端機對話
2. `app/interfaces/line_gateway.py`：LINE Webhook 轉接閘道器

為了達成 Phase 8 的目標——建立一個具備對話、執行軌跡（Execution Trace）、MCP 與 LINE 控制面板的現代 Web 互動 Demo，我們必須建立正式的 **Web HTTP Gateway**。
- 前端（瀏覽器）不可以直接存取內部 Python 物件、MCP Manager、A2A Client、Memory DB 或 LangGraph 狀態。
- 必須透過標準、型別安全、結構化的 HTTP REST / JSON 契約與後端對話。
- 必須嚴格維持 `HTTP Transport ≠ Application Service` 的分層架構。

## 5. 核心觀念與技術解析 (Important Concepts)

### (1) DTO (Data Transfer Object) 與 Domain Model 分離
- **Domain Model**（領域模型）：如 `TaskPlan`、`ExecutionResult`、`AggregatedResult`、`AIMessage`。這些是系統核心在思考、規劃與調度時使用的內部資料結構，可能包含系統內部連線資訊、內部狀態列舉與敏感細節。
- **DTO**（資料傳輸物件）：如 `ChatRequest`、`ChatResponse`。這些是向外部客戶端（如瀏覽器前端）公開的契約。
- **為什麼要分離？**
  1. 避免內部重構影響對外 API 契約（API Stability）。
  2. 避免將敏感資訊（如內部 Token、連線 URL、資料庫異常細節）洩漏給前端（Security Boundary）。

### (2) HTTP 傳輸成功 vs 應用層業務失敗 (Application Failure Semantics)
- **HTTP 400 (Bad Request)**：請求本身的格式或語法錯誤（例如傳入空白訊息、缺少必要欄位）。
- **HTTP 500 (Internal Server Error)**：伺服器內部發生未預期的程式崩潰或未捕捉的例外。
- **HTTP 200 (OK) + status="failed"**：HTTP 傳輸與調度流程順利執行完畢，但業務層面（例如外部 PCforge 代理人離線、指定的 MCP 工具不存在）判定任務失敗。這種情況屬於正常的業務執行結果，不應被誤判為 HTTP 500。

### (3) 長生命週期服務 (Service Lifetime & Dependency Injection)
- `OrchestrationService` 管理著多個 MCP 連線池、A2A 發現服務與記憶庫介面。
- 若在每次 HTTP Request 中重新 `new OrchestrationService()`，會造成伺服器頻繁重啟子程序與資料庫連線，效能低落。
- `create_web_app(orchestration_service=...)` 採用工廠模式與依賴注入（Dependency Injection），在 App 啟動時建立一個長期存活的實例（Long-lived），並允許測試時注入 Mock 實例。

## 7. 初學者解說 (Beginner Explanation)
> **什麼是 Web API Gateway？**
> 想像 M.Ber 是一家餐廳的「後廚總管」（`OrchestrationService`），負責調度廚師（Planner）、烤箱與攪拌機（MCP 工具）以及外送員（A2A 代理人）。
> 先前的命令列 CLI 就像是經理直接在後廚跟總管說話；LINE Webhook 就像是 LINE 傳真機。
> 這次我們建置的 **Web API Gateway**，就像是在餐廳前台設置了一個乾淨標準的「點餐櫃檯」：
> 1. 客人（前端瀏覽器）只能在櫃檯出示菜單上規定的點餐單（`ChatRequest` DTO）。
> 2. 櫃檯人員會先檢查點餐單有沒有寫字（400 驗證）。
> 3. 櫃檯將需求交給後廚總管處理。
> 4. 處理完成後，櫃檯將成品裝入漂亮的餐盒（`ChatResponse` DTO）交還給客人。
> 客人不需要知道後廚用了幾把刀或烤箱的插座在哪裡（封裝與資訊安全）。
